ISA: Live Blueprint Technical Specification

Project Vision: Bidirectional Visual Development Environment (IDE + CMS/CRM).

Core Concept: "Wire Logic, Not Code." Connecting nodes modifies actual source files and runtime state instantly.

Current State: ViRU5 V5 (Static Visualization).

Target State: ISA (Interactive System Architecture) - Automated Crawling + Live Editing.

1. Optimal Tech Stack

Frontend (The Blueprint)

  • Core React 18 + TypeScript (Component ecosystem, type safety).
  • Canvas PixiJS / React Pixi (High-performance node rendering, WebGL).
  • Editor Monaco Editor (VS Code engine for inline code editing).
  • State Zustand (Lightweight state management for complex graph data).
  • Comms Socket.io Client (Real-time sync with backend).

Backend (The Engine)

  • Runtime Node.js + Fastify (Low latency, JS ecosystem compatibility).
  • Parsing TS-Morph / Babel / PostCSS (AST manipulation for safe code refactoring).
  • DB PostgreSQL + pgvector (Relational data + semantic search for code).
  • Cache Redis (Pub/Sub for multi-user collaboration).
  • Sandbox Docker / WebContainers (Isolated code execution & preview).

Infrastructure

  • Hosting AWS Vercel (Frontend) + EC2/Fargate (Backend).
  • VCS GitHub API (Direct commit/push from blueprint).

  • Security: All code execution happens in ephemeral Docker containers. No direct host access.

3. Core Functionality Modules

A. Visual Editor (The Canvas)

  • Infinite Pan/Zoom: WebGL-based rendering for 10,000+ nodes.
  • Smart Wiring: Auto-snap connections based on type compatibility (e.g., CSS Node → HTML Element).
  • Context Menu: Right-click node to Refactor, Delete, Duplicate, or View Git History.

B. Bidirectional Sync (The Core)

  • Code → Visual: File save triggers AST re-parse, updates graph automatically.
  • Visual → Code: Disconnecting a wire removes the import or link tag in source.
  • Live Preview: Changes reflect in embedded browser instantly (HMR).

C. CMS/CRM Layer (The Application)

  • Data Nodes: Visual representation of Database Tables (SQL/NoSQL).
  • API Nodes: Visual endpoints (GET/POST) connected to Data Nodes.
  • User Mgmt: Visual role assignment (Admin → Can Edit Wire, User → Read Only).

5. Technical Risks & Mitigation

  • AST Complexity: Parsing dynamic JS can fail. Mitigation: Use TypeScript strict mode where possible; fallback to regex for unknown patterns.
  • Performance: 10k nodes lagging. Mitigation: Level-of-Detail (LOD) rendering in PixiJS; virtualize DOM.
  • Security: User code execution. Mitigation: Strict Docker sandboxing; no network access from sandbox except via proxy.
  • State Sync: Conflict when two users edit same node. Mitigation: Operational Transformation (OT) or Yjs for CRDT sync.

6. Success Metrics

  • Parse Speed: <30s for 10k file repository.
  • Sync Latency: <100ms from Wire Change to Preview Update.
  • Accuracy: 95%+ import/connection detection rate.
  • Stability: Zero data loss on disconnect (auto-save every 5s).
